# SDV向け AI 開発基盤の提案（ドラフト）

対象: デンソーテン イノベーション創出センター AIグループ  
前提: 世の中の汎用LLMをそのまま車に載せるのではなく、**HMIと車載ソフトウェアの強み**で差別化する。

## 1. どのLLMをどう組み合わせるか

車と開発机ではモデルを分ける。一つの巨大モデルに全部やらせない。

| 層 | モデル | 役割 | 理由 |
|----|--------|------|------|
| 車載・常時 | 数万〜数百万パラメータの分類/時系列モデル（本リポジトリの Copilot） | 認知負荷、視線、割り込み可否 | レイテンシ・電源・再現性 |
| 車載・断続 | 1B級 SLM（Ollama / llama.cpp、量子化） | 発話の言い換え、エラーの平易化 | オフライン、個人データが外に出ない |
| 開発机 | Cursor 内の LLM（Pro 契約） | 実装、テスト、設計レビュー | 予算内、コードに強い |
| クラウド（開発のみ） | 必要なら後段。推論APIは原則使わない | 大規模実験、データ設計 | 車載品質プロセスと分離 |

効率の要点は **ルータ** です。

1. センサーと状態モデルが先に動く  
2. ポリシーが「LLMを呼んでよいか」を決める  
3. 呼ぶ場合も出力は **文言** だけ。アクチュエータ指令のJSONはスキーマで落とす  

過負荷・衝突余裕不足では LLM を切る。これがコストも品質も一番効く。

## 2. Agentic 開発の使い方

エージェントは **車両の中** ではなく **開発ライン** に置く。

推奨エージェント（人間がオーナー）:

| エージェント | 入力 | 出力 | 人が承認するもの |
|--------------|------|------|------------------|
| Spec Agent | 要求・HMI制約 | テストケース草案 | 安全要求の採否 |
| Implement Agent | テストと許可インターフェース | コード差分 | マージ |
| Eval Agent | シーンセット | 誤検知レポート | リリース可否 |
| Artifact Agent | ONNX | S3/バージョン | 配布先 ECU プロファイル |

車両側エージェント（将来）はツールを HMI と情報系だけに閉じる。開発エージェントは Week 2 以降、`process/README.md` の境界で足す。

## 3. 人とAIのプロセス

```
要求（人）
  → 安全境界・許可リスト（人、変更はレビュー必須）
  → 失敗シーン設計（人+AI下書き）
  → 実装（AIが主、人が読む）
  → 自動テスト（AI追加、人が観点不足を指摘）
  → モデルカードと既知失敗（人）
  → デモ/顧客仮説（人）
```

AIに任せてよい: ボイラープレート、ONNX出力、単体テスト、ドキュメント整形、ログの要約  
人が持つ: 危害分析、許可アクション、データ倫理、リリース判断、顧客に出す約束

## 5. モビリティでの実現と品質

デンソーテンが既に強い領域（HMI、音響、車載ソフト、OEMインターフェース）に、**先読みして情報を減らす** モデルを載せる。生成AIで「何でも話す車」を先に作らない。

品質の最低セット:

1. **インターフェース凍結** — Copilot が出せるアクションは許可リストのみ  
2. **非干渉** — ブレーキ/操舵/スロットル文字列が成果物に出たら CI 失敗  
3. **シーン回帰** — 過負荷・安定・TTC短の3本は毎回実行  
4. **説明責任** — 出力に `reason` と `safety_mode` を必ず付ける  
5. **オフライン優先** — クラウドLLMは開発網。量産経路に混ぜない  
6. **サイレント劣化監視** — 実車ログではラベルなしでも、ポリシー発火率の急変を見る  

機能安全（ISO 26262）上、LLMをASIL部品にしない。QMのHMI支援に閉じ、SOTIFでは「情報過多による注意散漫」を危害として扱う。ここが汎用AI企業との差分になる。

## 6. イノベーションセンターで矢継ぎ早に試す型

毎回同じ箱にアイデアを流す。

```
仮説（誰の、どの瞬間の、何の負荷を減らすか）
  → 合成シーン10本
  → 小型モデルまたはルール
  → 許可HMIアクション
  → デモ脚本1本
  → Go / No-Go（OEMに見せるか、捨てるか）
```

最初の3アイデア候補:

1. 本 Copilot（認知負荷でHUD密度を変える）— 今の30日対象  
2. 整備・工場向け：CAN異常の「技師向け要約」はクラウドSLM、運転中は出さない  
3. 音声HMI：インテントは小型分類、応答文だけSLM。割り込み可否は状態モデル

未実現だが強みが生きる点は、**モデル精度そのものより、車のどの層にどの知能を置くか** を製品として設計できること。
